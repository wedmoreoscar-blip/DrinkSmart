# Context Audit

Use this read-only workflow when asked to understand the repository, reconcile historical records, or
recommend workflow/setup changes after broad review.

1. Inventory the requested code, configuration, instructions, skills, task records, history, and
   imported-session sources before claiming coverage.
2. Separate current enforced code/configuration from locked decisions, pending intentions, generated
   handoffs, historical context, and machine-local state.
3. Verify drift-prone claims against current code and Git state.
4. Report exclusions and discrepancies with exact file references.
5. Recommend changes only. Do not edit unless the user separately authorizes implementation.

Never describe a sampled scan as exhaustive. State what was and was not read.
