## Completed — the live `generate-plan` 502 is fixed, verified against the deployed function

The previous session handed over an unexplained HTTP 502 on the deployed `generate-plan`. It is
resolved and confirmed live on **version 11**: three consecutive probes returned HTTP 200 with real
AI plans in **3.3s / 3.7s / 5.5s**, all inside the ±10% ethanol gate. Before this session the
function 502'd on every call; after the first fix it worked but took 22–33s against a 15s client
timeout, so every user still received a greedy fallback.

**Root cause.** A **jurisdiction guardrail on the OpenRouter account blocks every CN-headquartered
provider.** DeepSeek is CN-headquartered, and the function pinned `only: ["deepseek"]` with
`allow_fallbacks: false`, so the candidate set was always empty and OpenRouter returned 404 — which
`index.ts` mapped to a generic 502. Two earlier diagnoses in this session (account data policy, then
the reasoning parameter) were wrong and were corrected by measurement; see the artifact below.

Changes, all in the working tree and all deployed as v11:

- **Provider** `only: ["coreweave", "wafer"]`, `order` preferring CoreWeave, `allow_fallbacks: true`
  between those two only. Chosen by a 30-trial-per-provider benchmark across all 20 reachable hosts.
- **Reasoning** expressed as `reasoning: { enabled: false }`. `effort: "none"` is not a supported
  effort for this model; `effort: "low"` does not disable reasoning (measured 400 tokens vs 0).
- **`calculate_ethanol` retained** after being removed and reinstated on evidence: with it, 30/30
  plans cleared the gate (worst deviation ±5%); without it 29/30 cleared (worst −16%).
- **Assistant-message echo sanitised** — `role`/`content`/`tool_calls` only. Replaying the raw
  message 400s on CoreWeave with `duplicate field reasoning_content`. **This latent defect predates
  the session** and was masked only while a single-tool flow never reached round two.
- **`EDGE_FUNCTION_TIMEOUT_MS` 15s → 22s.** Now ~4× headroom against a 5.5s observed end-to-end max.
- **Custom drinks bug fixed** (unrelated, reported mid-session). A drink kept via "keep it" is stored
  as category `custom`; `pickerCategoryFor` maps that to `null` and `handleAddSelected` never sets
  `isCustom`, so `planGroups` silently dropped the entry with `if (!label) continue`. It counted
  toward ethanol/BAC but rendered in no panel, leaving it with no lock or delete control. Unmapped
  categories now fall back to the Custom drink panel.
- **CLAUDE.md corrected** — three entries described the removed 6s/15s timeouts and the old
  multi-turn flow.
