## What was built

The relay previously had a human in the middle: Codex appends a command to the ledger, then Oscar
prompts the hub `Check the relay ledger.` The gap is structural — **nothing tells the hub the ledger
changed**, because every agent is reactive and a skill is inert text inside a turn that is already
happening. Neither can notice a file change.

`tools/relay-hub-waker` closes it. It is the only component that is not an agent: an ordinary OS
process watching the ledger's mtime, waking the hub only when `pending_commands` is non-empty. A
doorbell — it never claims, interprets, executes, or answers anything.

| Piece | What it is |
| --- | --- |
| `tools/relay-hub-waker` | The daemon |
| `tools/waker-daemon-start` | Launcher: `start` \| `stop` \| `restart` \| `status` \| `check` |
| `tools/traycer-identity` | Resolves epic + caller identity outside an agent shell |
| `relay-waker` skill | End-of-turn liveness check the hub runs |
| `a2a-hub-waker` agent | Idle; exists only to lend the daemon a sender id |
| `docs/agent_setup/RELAY_WAKER.md` | Authoritative: design, bring-up, terminal rules, log meanings |

`codex-tui-relay/SKILL.md` is now the single entry point: it opens with a five-part map of the system,
each part named against the file authoritative for it, and step 6 has Codex check and start the daemon.
`check-agent-setup` enforces those pointers, so the integration cannot silently rot again — it did once
this session, and the daemon and its sender agent became undiscoverable from the skill.

## Findings that cost real time

- **Detached processes launched from an agent shell are reaped with Traycer.** They inherit the cgroup
  `ai.traycer.host.service`; `setsid` escapes the *session*, not the *cgroup*. The daemon and both
  visualiser servers died together, three times in one evening. This is why local tooling keeps
  "silently disappearing". A `systemd --user` unit is the fix and was declined as not worth the upkeep.
- **Codex's sandbox denied network**, so every `traycer` call failed while filesystem work succeeded —
  a fingerprint that reads exactly like a code bug. `.codex/config.toml` now sets `network_access = true`.
- **Only an agent's own shell inherits the Traycer ids.** A UI terminal tab does not, which made both
  the daemon launcher and the visualiser unusable from an ordinary terminal. `tools/traycer-identity`
  resolves them instead.
- **`writespec-guard` denied its own commit**, because the message discussed `traycer agent send`. It
  matched the phrase anywhere in the command; it now detects an invocation.
- **The launcher reported a false failure** on a slow start: it took the pidfile only after two
  ~3.3s name lookups, against a 5s wait. Pidfile first, 30s wait.
